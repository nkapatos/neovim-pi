1. INTRODUCTION					*neovim-pi-introduction*

neovim-pi runs the Pi coding agent (https://github.com/earendil-works/pi) and
renders its state inside Neovim. Pi owns all agent state (sessions, models,
tools, approvals); Neovim paints what Pi reports and forwards user input.

This is an early implementation. Neovim spawns `pi --mode rpc`, renders the
streaming transcript (assistant text, thinking, and tool calls) in a scratch
buffer, and provides a real input buffer to compose prompts. Pi owns all
session state; Neovim only renders what Pi reports.

==============================================================================
2. REQUIREMENTS					*neovim-pi-requirements*

- Neovim >= 0.12.5.					*neovim-pi-nvim*
- The `pi` executable on `$PATH`.			*neovim-pi-pi*
- The experimental `ui2` module is used when available; otherwise the legacy
  messages and cmdline UI is used.

==============================================================================
3. INSTALLATION					*neovim-pi-installation*

Native package (|packages|). Clone into a `pack/*/start/` directory for
automatic loading: >sh
	git clone https://github.com/nkapatos/neovim-pi \
	  ~/.local/share/nvim/site/pack/core/start/neovim-pi
<
Alternatively install into `pack/*/opt/` and load it with |:packadd|: >vim
	:packadd neovim-pi
<

With the experimental |vim.pack| manager, add the following to your `init.lua`
and restart Neovim: >lua
	vim.pack.add({ 'https://github.com/nkapatos/neovim-pi' })
<

4. COMMANDS					*neovim-pi-commands*

:Pi							*:Pi*
	Open the chat + input layout (chat on top, input below) and start
	`pi --mode rpc` in the current project directory if it is not already
	running. One Neovim instance maps to one Pi process.

:PiStart					*:PiStart*
	Interactive launch builder: choose session mode, project trust, model,
	tool allowlist, and session name; then show the exact command, cwd, and
	trust, and start on confirmation.

:PiSend {text}					*:PiSend*
	Send a prompt to the running agent. Starts a session first if needed.

:PiAbort					*:PiAbort*
	Abort the current operation (also `<Esc>` in the chat buffer).

:PiModel					*:PiModel*
	Pick a model with `vim.ui.select` (built from `get_available_models`)
	and switch the running session to it.

:PiNew						*:PiNew*
	Start a fresh session in the running process and clear the transcript.

:PiResume {path}					*:PiResume*
	Resume a session by explicit path (`switch_session`) and reload the
	transcript. Session listing is planned for a later iteration.

:PiFork {entryId}				*:PiFork*
	Fork at an explicit session entry id and reload the transcript.

:PiCmd						*:PiCmd*
	Show the exact `pi …` command, cwd, and effective trust that `:Pi` would
	use (or that the running session used).

:PiTrust					*:PiTrust*
	Show the effective project-trust decision for the project root.

:PiStop						*:PiStop*
	Stop the Pi process by closing its stdin (SIGTERM after a short grace
	period).

:PiStatus					*:PiStatus*
	Show plugin and session status.

The session statusline shows the current model, thinking level, and whether the
agent is idle or streaming.

==============================================================================
4a. INPUT BUFFER				*neovim-pi-input*

The input is a normal Neovim buffer (multi-line aware), not a one-line prompt:

- In insert mode, `<CR>` inserts a newline and `<C-s>` sends.
- In normal mode, `<CR>` sends.
- `<C-c>` returns to normal mode. `<Esc>` in the chat window aborts.

If your terminal swallows `<C-s>` (XOFF), use `<Esc>` then `<CR>` to send.

==============================================================================
4b. LAUNCH & PROJECT ROOT			*neovim-pi-launch*

The spawn cwd is resolved LSP-style. A project `.pi` directory wins (Pi reads
project settings from `cwd/.pi`, so the spawn cwd must own the nearest `.pi`);
`$HOME/.pi` is ignored because that is Pi's global config, not a project marker.
Otherwise the nearest ancestor of the current buffer (or the cwd) containing a
generic marker (`.git`, `.hg`, `package.json`, `pyproject.toml`, `Cargo.toml`,
`go.mod`, `Makefile`) is used. Override the generic markers with
`require('pi').setup({ root_markers = { ... } })`.

The launch spec mirrors Pi's flags and is configurable with
`require('pi').setup({ launch = { ... } })`: `session` (`new`, `continue`,
`resume`, `none`, or a session path), `provider`, `model`, `thinking`, `name`,
`tools`, `exclude_tools`, `no_tools`, `no_builtin_tools`, `extensions`,
`no_extensions`, `no_skills`, `no_context_files`, `approve` (`default`,
`approve`, `no-approve`), `session_dir`, and `extra` (raw args).

In RPC mode Pi never prompts for project trust; without `--approve`/`-a` or
`--no-approve`/`-na` it silently applies the global `defaultProjectTrust`
setting. `:PiTrust` reports which applies and whether the project has
project-local resources (`.pi/`, `.agents/skills`) that the decision affects.

==============================================================================
4c. EXTENSION UI				*neovim-pi-extension-ui*

Pi extensions can request user interaction over RPC. Neovim renders them
generically:

- `select`, `confirm`, `input` use `vim.ui.select` / `vim.ui.input`.
- `editor` opens a floating multi-line buffer (`<C-s>` submits, `<Esc>` cancels).
- `notify` maps to |vim.notify|; `setStatus` appears in the session statusline;
  `setWidget` appears in the input window's winbar; `setTitle` sets the terminal
  title; `set_editor_text` prefills the input buffer.

Dialog responses are sent back as `extension_ui_response`. Timeouts are handled
by Pi; the client does not track them.

5. HEALTH					*neovim-pi-health*

						*:checkhealth-neovim-pi*
:checkhealth neovim-pi
	Report the Neovim version, `ui2` availability, and whether `pi` is on

6. CONFIGURATION				*neovim-pi-configuration*

There are no user options yet. `require('pi').setup({})` is called
automatically when the plugin loads; calling it again is a no-op.
